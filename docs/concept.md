# arvex — プロジェクト構想

## 一文サマリ

arvex が作るものは、
**学生団体を発見し、理解し、仮説を立て、先に提案用HPを生成し、その反応を学習しながら受注率を高めていく自動化システム**である。

表向きは「学生団体・サークル向けHP制作サービス」だが、本質は受託制作会社ではない。
**学生団体データベース × 提案自動化 × HP生成 × 営業導線** を一体化した仕組みを作る。

---

## 1. 何を作るのか

### 1.1 目的

学生団体・サークルに対して、**先に叩き台のHPを見せる**ことで会話を生み、そこから受注・ヒアリング・知見蓄積につなげる。

### 1.2 相手に提供するもの

いきなり正式サイトではなく、**提案用デモHP**を提供する。
これは「こういう見せ方ができます」「こういう課題を解けます」と示すための叩き台。

### 1.3 対象団体の2類型（初期仮説）

arvex は対象団体を次の2つに分類して扱う。
ただし**この2分類はあくまで出発点の仮説**であり、実データ（提案への反応、ヒアリング結果）に基づいてフェーズ6の学習ループで随時見直す。
初期段階では「分類を厳密に固めてからテンプレを作る」のではなく、**ゆるいタグ付けから始めて、反応データで分類軸そのものを育てる**方針を取る。

#### 集客型

人を集めたい組織。サークル、部活、募集を強くしたい団体など。
→ **新歓応募・参加・見学につながるHP**を提案する。

#### 信用型

外部から信頼されたい組織。学生団体、ボランティア、地域連携、教育支援など。
→ **活動実績・理念・問い合わせ窓口・対外信用を整えるHP**を提案する。

### 1.4 蓄積する4つの資産

| 資産 | 内容 |
| --- | --- |
| 団体データ | 団体名、大学名、SNS、活動内容、発信頻度、窓口、実績 |
| 分類と仮説 | 集客型/信用型の判別、課題仮説、刺さりそうなHP方針 |
| 提案素材 | 提案用HP、原稿、画像、提案文、構成テンプレ |
| 学習データ | どんな団体に何が刺さったか、どこで受注になったか |

### 1.5 作る4つのコンポーネント

1. **団体DB** — 団体情報・分類・課題仮説・提案状況・受注状況の土台。
2. **情報収集・整形の仕組み** — SNSや大学ページから情報を取得しDBに入れる。
3. **提案用HP生成の仕組み** — 団体情報から構成・原稿・素材・デザインを生成してデモHPを作る。
4. **営業・学習の仕組み** — 提案送付・反応記録・ヒアリング・受注判定・改善分析を記録・再利用する。

### 1.6 Claude Code まわりの運用構成

Claude Code を使う前提で、以下を整える。

| 種類 | 役割 |
| --- | --- |
| `CLAUDE.md` | ルールの土台 |
| `skills` | 業務ごとの手順書 |
| `subagents` | 役割ごとの担当 |
| `hooks` | 品質管理・自動整形 |
| `routines` / `/loop` | 定期実行・反復処理 |
| DB + Python スクリプト | 実データの本体 |

つまり arvex は、単なる「AIにHPを作らせる仕組み」ではなく、
**学生団体を見つけて、意味のある提案を自動で組み立てる業務OS**である。
