# arvex — 業務フロー

全体は次の6段階で回る。

**基盤整備 → 候補発見 → 団体理解 → 提案生成 → 提案実行 → 本制作・学習蓄積**

```
[1] 基盤整備
      ↓
[2] 候補発見
      ↓
[3] 団体理解
      ↓
[4] 提案生成
      ↓
[5] 提案実行
      ↓
[6] 本制作・学習蓄積 ──→ (改善を [1][3][4] へ還元)
```

---

## 1. 基盤整備

後続の工程が回るための土台を定義する。

> **重要な前提**: この段階で定義するものは全て **v0（初期仮説）** として扱う。
> 分類・テンプレ・スコア・提案文は、フェーズ6の反応分析を受けて継続的に書き換えていく前提で、**最初から作り込みすぎない**。

- **団体分類設計 (v0)** — 「集客型」「信用型」の2分類を出発点として定義。ただしこれは固定スキーマではなく、実データで軸そのものを更新していく前提のタグ。
- **情報項目設計** — 基本情報、活動情報、SNS情報、分類、課題仮説、提案状況、受注状況。
- **ソース定義** — 大学公式団体一覧、Instagram、X、イベントページ、Google検索など。
- **テンプレート定義 (v0)** — 集客型用・信用型用の提案HP構成テンプレ。最初は最小構成で用意し、受注・反応データを受けて型を増やす/統合する。
- **提案文テンプレート定義 (v0)** — DM、メール、問い合わせフォーム送付文の型。同様に v0 として用意し、反応率をもとに改善していく。

---

## 2. 候補発見

提案対象になりうる団体を見つける工程。

- **候補探索** — 対象大学・ジャンル単位で団体候補を探す。
- **候補一覧化** — 見つけた候補を一時的に一覧化。
- **名寄せ** — 重複候補を統合。
- **実在判定** — 本当に存在する団体かを確認。
- **稼働判定** — 現在も活動している団体かを確認。

---

## 3. 団体理解

その団体にどんな提案をすべきかを理解する工程。

- **基本情報登録** — 実在・稼働と判断した団体を本DBに登録。
- **団体分類** — 集客型/信用型を判定。
- **優先度スコアリング** — 提案順序を決定。
- **詳細情報収集** — 活動内容、実績、募集情報、理念、問い合わせ先を追加収集。
- **情報要約** — HP制作に使いやすい形へ整理。
- **課題仮説生成** — 集客導線不足、実績訴求不足、説明不足、問い合わせ導線不足などを仮説化。
- **提案テーマ決定** — 新歓導線強化、信用強化など切り口を決定。

---

## 4. 提案生成

団体に見せるためのデモHPを作る工程。

- **構成方針生成** — 誰向けに、何を目的として見せるサイトかを定義。
- **サイトマップ生成** — 必要なページ・セクションを決定。
- **セクション設計** — トップや各ページの構成を決定。
- **原稿生成** — キャッチコピー、見出し、本文、CTAを作る。
- **素材要件定義** — 必要な写真・ビジュアルを洗い出す。
- **素材生成** — 既存公開素材を整理し、不足分を生成。
- **デザイン仕様生成** — 配色、フォント、密度、表現トーンを決定。
- **デモHP実装** — 提案用の叩き台サイトを実装。
- **提案用URL発行** — 相手が見られるURLとして保存。

---

## 5. 提案実行

作ったものを相手に届けて反応を取る工程。

- **提案対象管理** — どの団体に何をいつ送るかを管理。
- **提案文生成** — 団体ごとに個別化した送付文を作成。
- **提案送付** — メール、DM、問い合わせフォーム経由で送付。
- **反応取得** — 返信、クリック、興味、追加質問を記録。
- **ヒアリング実施** — 反応があった相手から真のニーズを聞き取る。
- **ヒアリング反映** — 聞き取った内容をDBへ反映。
- **受注判定** — 本制作に進むかを判断。

---

## 6. 本制作・学習蓄積

受注後の制作と、今後の改善のための学習工程。

- **本制作要件整理** — 正式サイトに必要なページ、機能、運用方法を整理。
- **正式サイト制作** — 提案用デモをもとに正式版を制作。
- **納品管理** — 公開、納品日、URL、プラン内容を案件単位で記録。
- **反応分析** — どんな団体にどんな提案が刺さったかを分析。
- **分類軸の見直し** — 「集客型 / 信用型」の2分類が実データと合っているかを検証し、必要なら軸の分割・統合・追加を行う（例：「集客型」を "新歓特化型" と "通年募集型" に分ける、など）。
- **テンプレ改善** — テンプレサイトや提案文を改善。分類軸が変わった場合はテンプレ構成もそれに追従。
- **スコアリング改善** — 反応・受注結果をもとに優先度判定ロジックを改善。

---

## フローの回し方

この6段階は単発ではなく、**6 → 1/3/4 への学習フィードバック**によってループする。
反応・受注データを蓄積するほど、**分類軸そのもの**・候補発見の精度・課題仮説の的確さ・提案テンプレの打率が上がっていく設計。

初期段階（データが少ない時期）は分類・テンプレ・スコアを v0 のまま使い、**フィードバックが溜まってからテンプレと分類を育てていく**のが基本姿勢。
